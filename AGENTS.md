## Project rules
- Site-specific and overall leaderboards share the same XC query and display; only the optional site filter differs, keeping scoring and track access consistent.
- Relief layers are composited into bounded native-resolution tile surfaces, invalidated by source identity and appearance; triangle candidates reuse pairwise distances without changing scoring.
- Turn-key input preserves the initial press timestamp across keyboard auto-repeat so desktop and touch long holds use the same simulation boost.
- Launches are restricted to THERMAL_REGION. Regional KK7 tiles are bundled under public/kk7 (XYZ, z12, excluded from PWA precache) as fallback; a quarterly managed schedule copies fresh tiles in small batches into the private kk7-tiles bucket and writes manifest.json, served via /api/public/kk7/* with versioned device caches. Tiles load on demand into Cache Storage once per device (visible + 3x3 around pilot); all kk7.ch requests pass the 10 req/s limiter in src/lib/kk7Limiter; full-region thermal coverage uses compressed per-tile PNGs, sparse byte heat arrays and a bounded visible-bitmap cache; never allocate a single country-sized canvas. Regional coverage is reused independently of moving terrain windows, with local mosaics beyond its bounds.
- Track overviews reuse the flight map tile renderer and launch-relative Mercator projection with its 55% vertical anchor; fit the full track and read the selected map style. Expandable post-flight maps use an independent d3-zoom transform converted into the same world-space camera so tiles and tracks remain aligned.
- Offline support is opt-in: generate the app-shell worker with vite-plugin-pwa, register only through offline-worker with preview guards, and persist CORS-readable regional tiles in a bounded Cache Storage cache; missing offline terrain/thermal coverage must fail or pause rather than fabricate data.
- Cache static contour paths in bounded, terrain-keyed world-space windows; transform them at draw time and recompute the exact flight-altitude contour each frame so performance improvements do not delay altitude feedback.
- Compute glide boundaries in pure game logic from current speed/vz, stopping at first terrain contact per ray and omitting unloaded coverage; this prevents reachable outlines behind blocking ridges.
- Free launch selection uses the same inverse Mercator projection as the flight map and a single DEM tile to preview ground altitude; coordinate-specific site IDs isolate terrain/thermal caches. Flight terrain and KK7 coverage are prefetched as moving windows and swapped together, always using original launch-relative coordinates; pause before exhausting loaded coverage and retry failed loads to avoid fabricated terrain or lift on long flights.
- Simulation logic lives in src/game/* as pure TS (terrain, thermals, physics, sun, audio); React components only render and wire input — keeps the engine testable. Additional sunlit-surface lift uses sparse position-stable neighbouring cells, loaded terrain and solar exposure/shadow checks, independently of KK7 imagery, so it remains bounded and continuous across terrain windows. Imported FlyXC tasks are guidance only, never scoring; flights end on landing. The HUD "XC" distance is the XContest-style optimized free distance (max over downsampled track points of launch→point→current position, sim.xcDist), and XC speed is that distance divided by flight time.
- noUncheckedIndexedAccess is off: the engine does hot-loop typed-array indexing where per-access undefined checks add noise.
- Display the real relief using browser-loaded swisstopo colored relief WMTS tiles and pure launch-relative Mercator projection in src/game/swissMap.ts; tiles use the highest WMTS level that renders ≥256 device pixels per tile (reliefLevel, capped at 17) so the map stays sharp on high-dpi screens and when zoomed in. Flight terrain is loaded from open Terrarium DEM tiles in src/game/realTerrain.ts using the same projection, with procedural terrain only as offline fallback.
- Use independent d3-zoom canvas transforms for the map and heading-relative side profile; the profile samples existing terrain and heading-line airspace intersections (including polygon holes and terrain-relative AGL limits), sharing the map visibility toggles without affecting physics.
- Render real lake geometry (swisstopo `ch.bafu.vec25-seen`), major rivers (`ch.bafu.vec25-gewaessernetz_2000`) and forest geometry (swisstopo `ch.swisstopo.swisstlm3d-wald`) over the relief with cached alpha-preserving tints; apply semantic CSS relief filters only to base tiles so flight symbols, water and forests remain legible.
- Preprocess relief filters and lake tints once on native-resolution tile canvases, stored in a bounded least-recently-used browser cache keyed by URL and appearance; the animation loop only blits these surfaces to avoid repeated high-DPI filter work.
- Flight thermals sample the full KK7 thermal raster with the same launch-relative Mercator as terrain; render the unchanged provider colors and map the palette to climb rates for simulated lift: blue = 1–3 m/s, rising through cyan/green/yellow to dark red = 6–9 m/s. Keep dataset settings centralized in the pure thermalRaster module, load and cache mosaics in loadThermalRaster with bounded concurrency and memory, invert TMS tile rows, and send the actual site hostname as src. Missing data must show retry rather than invented sources; keep KK7 attribution and CC BY-NC-SA notice visible.
- The unfinished XC triangle (src/game/xcTriangle.ts) is optimized over ≤70 downsampled track points once per second; FAI = every leg ≥28% of perimeter, closing cylinder = 20% of perimeter around the first vertex, one FAI sector per leg (on the side of the opposite vertex, labelled with min/max reachable perimeter) drawn as a cached world-space Path2D.
- Hot loops use src/game/fastMath (fastExpNeg, sqrt instead of Math.hypot) and cache per-cell sunlit-surface exposure per terrain and quantized sun; speed over precision for lift.
- User-facing updates go newest-first in src/game/changelog.ts; a new top id makes the start button glow.
